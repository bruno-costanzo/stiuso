# ciaobrowser — Implementation Plan

## What is this gem?

Say goodbye to the browser. ciaobrowser lets AI interact with your Rails app the same way users do — through your existing controllers, with the same authorization, validations, and business logic. No new endpoints, no duplicated code.

It uses an AI agent to read your controllers, models, routes, and validations, and auto-generates [fast-mcp](https://github.com/yjacquin/fast-mcp) tools from them. Your entire Rails app becomes an MCP server that any AI client can use — Claude Desktop, Cursor, ChatGPT, or your own WhatsApp/Slack bot via [RubyLLM](https://rubyllm.com).

The browser was the interface. Now AI is.

## Stack

- **fast-mcp**: MCP server infrastructure (tools, resources, SSE transport)
- **ruby_llm**: LLM client — powers both the install agent AND the internal chatbot
- **ruby_llm-mcp**: Connects RubyLLM to the MCP server so the LLM can call the tools

## Architecture

```
External clients (Claude Desktop, Cursor)
        │
        ▼
   fast-mcp server (/mcp/sse)
        │
        ▼
   app/tools/*_tool.rb  ← generated by ciaobrowser's AI agent
        │
        ▼
   Rails controllers (existing code, same auth, same logic)
        │
        ▼
   format.chatbot { "response hint" }  (optional)

Internal chatbot (WhatsApp, Slack)
        │
        ▼
   RubyLLM::Chat + ruby_llm-mcp client
        │
        ▼
   Same MCP tools (connects to own /mcp/sse)
```

## Usage

```ruby
# Gemfile
gem 'ciaobrowser'
```

```bash
rails generate ciaobrowser:install
rails generate ciaobrowser:tools profiles projects tasks
```

The `tools` generator doesn't use regex or templates — it runs a RubyLLM agent
that introspects your app, understands your code, and generates proper MCP tools.

## Phase 1: Gem scaffold

1. `bundle gem ciaobrowser`
2. Set up gemspec with dependencies: `rails >= 7.0`, `fast-mcp >= 1.0`, `ruby_llm`, `ruby_llm-mcp`
3. Create `lib/ciaobrowser.rb` entry point
4. Create `lib/ciaobrowser/version.rb`
5. Create `lib/ciaobrowser/railtie.rb` — registers generators with Rails
6. Create `lib/ciaobrowser/configuration.rb` — config object (API keys, model, etc.)
7. Add `Gemfile` with development dependencies (rspec, rubocop)

## Phase 2: Install generator (`rails generate ciaobrowser:install`)

Creates the initial setup in the host app.

**Generator:** `lib/generators/ciaobrowser/install/install_generator.rb`

**What it does:**
1. Runs `fast_mcp:install` if not already installed (creates `config/initializers/fast_mcp.rb`, `app/tools/`, `app/resources/`)
2. Creates `config/initializers/ciaobrowser.rb` with RubyLLM config (API keys, default model)
3. Prints next-steps instructions

**Template:** `lib/generators/ciaobrowser/install/templates/ciaobrowser.rb.tt`

## Phase 3: Agent tools (the introspection toolkit)

The AI agent needs tools to inspect the Rails app. Each tool is a RubyLLM::Tool
that the agent calls as needed during generation.

**Directory:** `lib/ciaobrowser/agent_tools/`

### read_controller_source

Reads the source code of a Rails controller file.

```ruby
class Ciaobrowser::AgentTools::ReadControllerSource < RubyLLM::Tool
  description "Reads the full source code of a Rails controller. " \
              "Use this to understand actions, before_actions, strong params, and respond_to blocks."

  params do
    string :controller_name, description: "Controller name without 'Controller' suffix (e.g. 'profiles', 'admin/users')"
  end

  def execute(controller_name:)
    path = Rails.root.join("app/controllers/#{controller_name}_controller.rb")
    return { error: "Controller not found at #{path}" } unless File.exist?(path)
    File.read(path)
  end
end
```

### read_model_source

Reads a model file to understand associations, callbacks, scopes.

```ruby
class Ciaobrowser::AgentTools::ReadModelSource < RubyLLM::Tool
  description "Reads the full source code of a Rails model. " \
              "Use this to understand validations, associations, callbacks, and scopes."

  params do
    string :model_name, description: "Model name in snake_case (e.g. 'profile', 'user')"
  end

  def execute(model_name:)
    path = Rails.root.join("app/models/#{model_name}.rb")
    return { error: "Model not found at #{path}" } unless File.exist?(path)
    File.read(path)
  end
end
```

### read_routes

Lists all routes for a controller, with HTTP methods and paths.

```ruby
class Ciaobrowser::AgentTools::ReadRoutes < RubyLLM::Tool
  description "Lists all routes for a given controller. " \
              "Returns HTTP method, path, and action name for each route."

  params do
    string :controller_name, description: "Controller name without 'Controller' suffix"
  end

  def execute(controller_name:)
    routes = Rails.application.routes.routes.select do |route|
      route.defaults[:controller] == controller_name
    end

    routes.map do |route|
      {
        action: route.defaults[:action],
        verb: route.verb,
        path: route.path.spec.to_s
      }
    end
  end
end
```

### read_schema

Returns column names, types, and nullability for a model's table.

```ruby
class Ciaobrowser::AgentTools::ReadSchema < RubyLLM::Tool
  description "Returns the database schema for a model. " \
              "Includes column names, types, nullability, and defaults."

  params do
    string :model_name, description: "Model class name (e.g. 'Profile', 'User')"
  end

  def execute(model_name:)
    klass = model_name.constantize
    klass.columns.map do |col|
      { name: col.name, type: col.type, null: col.null, default: col.default }
    end
  rescue NameError
    { error: "Model #{model_name} not found" }
  end
end
```

### read_validations

Returns all validations defined on a model.

```ruby
class Ciaobrowser::AgentTools::ReadValidations < RubyLLM::Tool
  description "Returns all validations for a model. " \
              "Includes which attributes are validated, the type of validation, and options."

  params do
    string :model_name, description: "Model class name (e.g. 'Profile', 'User')"
  end

  def execute(model_name:)
    klass = model_name.constantize
    klass.validators.map do |validator|
      {
        attributes: validator.attributes,
        kind: validator.kind,
        options: validator.options.except(:if, :unless)
      }
    end
  rescue NameError
    { error: "Model #{model_name} not found" }
  end
end
```

### read_file

Generic file reader for when the agent needs to look at something else
(parent controllers, concerns, lib files, etc.)

```ruby
class Ciaobrowser::AgentTools::ReadFile < RubyLLM::Tool
  description "Reads any file in the Rails project. " \
              "Use when you need to look at a concern, parent controller, " \
              "service object, or any other file to understand the full picture."

  params do
    string :path, description: "Path relative to Rails.root (e.g. 'app/controllers/concerns/authenticatable.rb')"
  end

  def execute(path:)
    full_path = Rails.root.join(path)
    return { error: "File not found: #{path}" } unless File.exist?(full_path)
    return { error: "Path is outside Rails.root" } unless full_path.to_s.start_with?(Rails.root.to_s)
    File.read(full_path)
  end
end
```

### generate_tool_file

Writes the actual tool file to `app/tools/`.

```ruby
class Ciaobrowser::AgentTools::GenerateToolFile < RubyLLM::Tool
  description "Creates a fast-mcp tool file in app/tools/. " \
              "The code must be a valid Ruby class inheriting from ApplicationTool (ActionTool::Base). " \
              "Use fast-mcp's arguments DSL with Dry-Schema syntax."

  params do
    string :filename, description: "Filename without path (e.g. 'update_profile_tool.rb')"
    string :code, description: "Full Ruby source code for the tool class"
  end

  def execute(filename:, code:)
    path = Rails.root.join("app/tools/#{filename}")

    if File.exist?(path)
      return { error: "File already exists: #{filename}. Use --force to overwrite." }
    end

    File.write(path, code)
    { success: "Created #{path}" }
  end
end
```

## Phase 4: The agent (`rails generate ciaobrowser:tools`)

**Generator:** `lib/generators/ciaobrowser/tools/tools_generator.rb`

The generator spins up a RubyLLM::Chat with all the agent tools, gives it a
system prompt, and asks it to generate MCP tools for the specified controllers.

```ruby
module Ciaobrowser
  class ToolsGenerator < Rails::Generators::Base
    argument :controllers, type: :array, banner: "controller [controller ...]"

    def generate_tools
      agent = RubyLLM.chat(model: Ciaobrowser.config.model)
      agent.with_tools(
        AgentTools::ReadControllerSource,
        AgentTools::ReadModelSource,
        AgentTools::ReadRoutes,
        AgentTools::ReadSchema,
        AgentTools::ReadValidations,
        AgentTools::ReadFile,
        AgentTools::GenerateToolFile
      )

      controllers.each do |controller_name|
        say_status :analyze, controller_name, :cyan

        agent.ask(<<~PROMPT)
          Generate fast-mcp tool files for the #{controller_name} controller.

          Instructions:
          - Use the available tools to read the controller source, model, routes, schema, and validations
          - For each action that makes sense as an MCP tool, generate a tool file using generate_tool_file
          - The tool must inherit from ApplicationTool (which is ActionTool::Base from fast-mcp)
          - Use the fast-mcp arguments DSL (Dry-Schema syntax): required(:name).filled(:string).description("...")
          - Write clear, specific descriptions that help an LLM understand WHEN and HOW to use each tool
          - The call method should contain the actual implementation (find record, update, etc.)
          - Consider authorization: if the controller has before_actions for auth, mention it in the description
          - If you need to understand a concern or parent controller, use read_file to look at it
          - Do NOT generate tools for actions that only render HTML forms (new, edit) unless they do something useful
          - Use your judgment on what makes sense as a chatbot tool
        PROMPT
      end
    end
  end
end
```

**What happens when you run `rails generate ciaobrowser:tools profiles`:**

1. The agent calls `read_routes(controller_name: "profiles")` — sees PATCH /profiles/:id, GET /profiles/:id, etc.
2. The agent calls `read_controller_source(controller_name: "profiles")` — reads the full controller
3. It sees `before_action :authorize_user` — notes the auth requirement
4. It sees `profile_params` with `.permit(:biography, :website)` — understands the writable fields
5. It calls `read_model_source(model_name: "profile")` — sees validations, associations
6. It calls `read_schema(model_name: "Profile")` — gets column types
7. With all this context, it calls `generate_tool_file` for each action that makes sense
8. The generated tools have proper descriptions, typed params, and real implementations

The agent can handle edge cases that regex never could:
- Controllers that inherit from a custom base class
- Params defined in a concern
- Complex authorization logic (Pundit, CanCanCan)
- Nested resources
- Custom actions beyond CRUD

## Phase 7: Internal chatbot bridge (V2)

For in-app usage (WhatsApp, Slack bots), provide a simple interface:

**File:** `lib/ciaobrowser/chat.rb`

```ruby
module Ciaobrowser
  class Chat
    def initialize(user:, model: nil)
      @user = user
      @model = model || Ciaobrowser.config.default_model
      @mcp_client = RubyLLM::MCP.client(
        name: "ciaobrowser",
        transport_type: :sse,
        config: { url: Ciaobrowser.config.mcp_url }
      )
    end

    def ask(message)
      chat = RubyLLM.chat(model: @model)
      chat.with_tools(*@mcp_client.tools)
      chat.with_instructions(system_prompt)
      chat.ask(message)
    end

    private

    def system_prompt
      "You act on behalf of user #{@user.name} (ID: #{@user.id}). " \
      "Use the available tools to perform actions. " \
      "Be concise and confirm what you did."
    end
  end
end
```

Usage in a WhatsApp webhook controller:
```ruby
response = Ciaobrowser::Chat.new(user: current_user).ask(message.text)
whatsapp_client.send_text(to: message.from, text: response.content)
```

## Implementation order

1. **Gem scaffold** — gemspec, entry point, railtie, version, configuration
2. **Install generator** — `ciaobrowser:install` with template
3. **Agent tools** — the 7 RubyLLM::Tool classes that inspect the Rails app
4. **Tools generator** — `ciaobrowser:tools` that runs the agent
5. **Tests** — for agent tools and generators
6. **README** — with usage examples

### V2 (after MVP works):
7. Dispatcher — automatic controller dispatch from tools
8. format.chatbot MIME type
9. Ciaobrowser::Chat — internal chatbot bridge
10. WhatsApp/Slack example integrations

## Key decisions

- **AI agent, not regex** — the agent understands code, handles edge cases, writes good descriptions
- **fast-mcp tools, not RubyLLM::Tool** — MCP gives interoperability with any client
- **Generator, not boot-time** — you control what's exposed, files are auditable
- **Agent writes the call body** — no TODO stubs, the agent implements the logic
- **No hardcoded skips** — the agent decides what makes sense, not arbitrary rules
- **RubyLLM used twice** — once to generate tools (at install), once to power the chatbot (at runtime)
